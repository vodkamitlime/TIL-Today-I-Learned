# DP(Dynamic Programming)에 대한 오해들

## 왜 DP 오해에 대해 이야기할까?

DP 는 지원자들 사이에서 종종 과대평가되기 때문이다.

우리는 지원자들로부터 다음과 같은 말을 자주 듣는다:

> "저는 어려운 DP(Dynamic Programming) 문제만 빼고 다른 모든 주제는 잘합니다. 그래서 인터뷰 준비가 안 됐다고 생각해요."

첫째, DP 는 인터뷰에서 점점 비중이 줄어드는 문제 유형이다. Google 과 Facebook 은 DP 만으로 풀어야 하는 문제(DP-Only)를 적극적으로 지양하고 있다.

**DP-Only 문제**란, (합리적으로) 오직 DP 로만 풀 수 있는 문제를 의미한다. 뒤에서 보겠지만, DP 는 사실 매우 광범위한 개념이다.

여전히 이런 문제를 내는 다른 회사들의 경우에도, 우리는 알고리즘 문제 중 DP-Only 문제의 비율이 약 3% 정도라고 추정한다. 이는 인터뷰 30번 중 1번 꼴이다. 현실적으로, 한 문제를 최적이 아닌 방식으로 풀었다 해도, 다른 인터뷰에서 잘한다면 여전히 오퍼(offer)를 받을 수 있다. 따라서 다른 모든 주제에 정말 능숙하다면, 이미 여러 곳에서 오퍼를 받고 있어야 정상이다.

## 오해 #1: 어려운 DP 문제가 흔히 출제된다

사람들이 Dynamic Programming 을 떠올릴 때, 대개 어려운 DP 문제를 떠올린다. 하지만 이런 문제는 그렇게 흔하지 않다.

이런 문제들은 어렵기 때문에 두려움의 대상이 되고, 사람들은 여기에 많은 시간을 쏟는다.

사실 DP 는 매우 넓은 범위를 다룬다. 부분 문제(subproblem)를 저장해두고 재사용할 때마다, 우리는 DP 를 사용하고 있는 것이다. 우리는 종종 인식하지 못한 채 DP 를 사용한다. 예를 들어, 이 강의의 다른 섹션에 등장하는 다음 문제들도 DP 를 사용한다:

```
1. 모든 DFS 문제: 그렇다, Depth First Search 도 DP 를 사용한다! 각 노드의 상태를 확인할 때, 우리는 동일한 부분 문제를 저장하고 재사용하고 있는 것이다.

2. Subarray Sum 문제 #1: 정수 배열이 주어졌을 때, 합이 최대가 되는 연속 부분 배열(contiguous subarray)을 찾는 문제. 배열에는 음수와 양수가 모두 포함될 수 있다.

3. Max Diff 숙제 #1: 2번의 거래(trade)로 얼마의 돈을 벌 수 있는가?

4. Backtracking 문제 #2: 4방향으로 이동 가능한 미로(Maze) 문제

5. Topological Sort 숙제 #1: 그래프의 지름(Diameter): 그래프가 주어졌을 때, 임의의 두 정점 사이의 가장 긴 경로의 길이를 찾는 문제.
```

또한, 많은 "DP 문제"들은 DP 없이도 풀 수 있다. 그렇다면 이런 문제들을 DP 문제로 분류해야 할까? 판단하기 어렵다.

DP 가 아닌 방식으로 문제를 풀었더라도, 좋은 코드를 작성하고 의사소통을 잘한다면 좋은 평가를 받을 수 있다. 물론, DP 를 사용해 더 나은 성능을 낼 수 있다면 그것은 덤(icing on the cake)이다.

## 오해 #2: 고난이도 문제 함정(Advanced Problem Fallacy)

정말 어려운 문제들을 연습하면 인터뷰 문제를 푸는 것이 더 쉬워질 것이라는 믿음이다.

결국, "Google 과 Facebook 문제보다 더 어려운 문제도 풀 수 있다면, 인터뷰는 쉬운 일이지 않을까?"라고 생각할 수 있다. 하지만 틀렸다. 그런 초고난도 문제들은 대개 인터뷰 수준의 문제와는 별 관련이 없으며, 많은 시간을 소모하게 만든다. 지적 호기심 차원이라면 괜찮지만, 원하는 직장을 얻는 데 도움이 될 것이라고 생각한다면 다시 고려해봐야 한다.

안타깝게도, Geeks4Geeks 같은 웹사이트들은 초고난도 문제를 보여줌으로써 성장한다. 사람들이 사이트에 오래 머물수록 그들에게는 이득이다. 하지만 이것이 실제 업계에서 인터뷰 때 묻는 것을 반영하지는 않는다.

## 오해 #3: 최적화 결벽증(Optimization Snobs)

안타깝게도, LeetCode 포럼에서 특정 풀이의 아주 작은 성능 개선에 집착하는 사람들을 볼 수 있다. 너무 많은 사람들이 잘 동작하는 좋은 풀이를 만드는 것보다, 알고리즘의 세세한 디테일에 집착한다. 이는 더 많은 알고리즘을 연습할 시간을 빼앗는다.

## 그래서 우리는 무엇을 해야 할까?

DP 에 대해서는, 이 섹션을 살펴보고 관련 문제들을 연습하는 것을 추천한다. 그 후에는 이 강의 전반에 걸쳐 DP 를 사용하는 문제들을 계속 만나게 될 것이고, 자연스럽게 익숙해질 것이다. 그다음에는 온라인에서 흔히 볼 수 있는 다른 문제들을 살펴보면 된다. 고난도 DP 문제는 그 이후에나 살펴보는 것을 권장한다.

## 배운 점:
- DP 는 "오직 DP 로만 풀 수 있는" 문제(DP-Only)로 한정하면 실제 인터뷰에서 차지하는 비중이 매우 작다 (약 3%).
- DFS, 부분 배열 최대합, 그래프 지름 찾기 등 이미 알고 있는 여러 알고리즘도 사실 DP 의 개념(부분 문제 저장 및 재사용)을 사용하고 있다.
- 고난도 문제를 많이 푼다고 해서 실제 인터뷰 대비에 비례해서 도움이 되는 것은 아니며, 오히려 시간을 낭비할 수 있다.
- 완벽한 최적화보다, 잘 동작하는 풀이를 명확한 코드와 커뮤니케이션으로 전달하는 것이 더 중요하다.
