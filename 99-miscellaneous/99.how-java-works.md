# Java는 어떻게 동작하는가? 어떻게 플랫폼에 독립적인가?

## C++ 와의 차이

C++ 프로그램을 컴파일하면, 대상 플랫폼(예: Windows, Linux)에서 실행되는 실행 파일(executable)이 생성된다. 예를 들어 Windows 에서는 .exe 파일이 생성된다.

Java 프로그램을 컴파일할 때는 JVM 컴파일러(javac)를 사용하여 바이트코드(Bytecode) 파일(.class 확장자)을 생성한다. 이 파일들은 JVM(Java Virtual Machine)이 설치된 어떤 플랫폼에서도 실행될 수 있다.

## 핵심 구성 요소

**javac** - Java Compiler
Java 코드(.java 파일)를 바이트코드(.class 파일)로 컴파일한다.

**JVM** - Java Virtual Machine
바이트코드를 네이티브 머신 코드(Native Machine Code)로 변환(번역)한다.

**JRE** - Java Runtime Environment
Java 애플리케이션을 실행하기 위한 소프트웨어이다. JVM 과 기타 라이브러리를 포함한다.

**JDK** - Java Development Kit
Java 애플리케이션을 실행하고 개발하기 위한 소프트웨어이다. JRE 와 함께 컴파일러, 디버거를 포함한다.

## Just In Time (JIT) 컴파일러

초창기 JVM 은 바이트코드를 한꺼번에 머신 코드로 컴파일했다. 하지만 현재 Java 는 JIT 컴파일러를 사용하는데, 이는 필요할 때 동적으로 많은 부분의 바이트코드를 컴파일한다.

**장점**: JIT 는 동적 런타임 정보(dynamic runtime information)에 접근할 수 있기 때문에, 이를 기반으로 최적화를 수행할 수 있다.

## 가비지 컬렉터 (Garbage Collector, GC)

Java 는 가비지 컬렉터(GC)를 가지고 있으며, 이는 백그라운드 스레드로 동작하면서 더 이상 사용되지 않는 할당된 메모리를 정리한다.

**장점**: 변수를 직접 해제(free)할 필요가 없다.

**단점**: 메모리가 제한된 시스템에서는 성능에 영향을 줄 수 있다.

가비지 컬렉션에 대한 자세한 내용은 이후 강의에서 다룬다.

## 배운 점:
- Java 가 플랫폼에 독립적인 이유는 컴파일 결과물이 특정 OS 의 실행 파일이 아니라, JVM 위에서 실행되는 바이트코드이기 때문이다.
- javac, JVM, JRE, JDK 의 관계와 역할을 명확히 구분해서 이해했다. (JDK ⊃ JRE ⊃ JVM)
- JIT 컴파일러는 런타임 정보를 활용해 동적으로 최적화할 수 있다는 점에서 AOT(Ahead-of-time) 컴파일과 차이가 있다.
- 가비지 컬렉터는 메모리 관리 부담을 줄여주지만, 메모리 제약이 있는 환경에서는 성능 트레이드오프가 있을 수 있다.
