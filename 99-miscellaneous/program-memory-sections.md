# 프로그램 메모리의 영역

## 프로그램 메모리의 4가지 영역

1. **Code** (코드 영역) - 실행할 명령어(instruction)를 저장한다.
2. **Data** (데이터 영역) - 전역 변수와 정적(static) 변수를 저장한다.
3. **Stack** (스택 영역) - 함수 호출 정보를 저장한다.
4. **Heap** (힙 영역) - 배열, 객체, 그리고 동적으로 할당되는 항목들을 저장한다.

## 관련 개념

- **Stack Overflow** - 스택 영역의 메모리가 부족해지는 현상
- **Heap Overflow** - 힙 영역의 메모리가 부족해지는 현상

## Java 에서의 참조(Reference)와 객체

Java 에서는 참조(reference)는 스택에 저장되고, 객체와 배열은 힙에 저장된다.

다음 코드를 보면:

```java
List list = new ArrayList();
```

`list` 변수는 참조(reference)이며 스택에 저장된다. 이 참조는 힙에 저장된 ArrayList 객체를 가리킨다(points to).

## 함수 호출과 스택 프레임

함수가 호출될 때마다 스택에는 새로운 스택 프레임(stack frame)이 생성된다. 이 프레임은 입력 인자(argument)와 지역 변수를 저장하기 위한 공간을 포함하는 메모리 영역이다. 이로 인해 함수 작업 시 익숙한 다음과 같은 특징들이 나타난다:

1. **각 함수는 인자의 복사본을 갖는다.**
   각 함수 호출은 새로운 메모리 영역(스택 프레임)을 갖기 때문에, 전달된 인자도 그 함수만의 복사본이 된다.

2. **다른 함수는 해당 함수 내에서 초기화된 변수를 볼 수 없다.**
   다른 함수는 이 함수의 스택 프레임에 접근할 수 없기 때문이다. 반면 전역 변수(global variable)는 여러 함수가 접근할 수 있는데, 이는 전역 변수가 모든 함수가 접근 가능한 **Data 영역**에 존재하기 때문이다.

3. **스택 트레이스(stack trace)가 생성되는 원리**
   각 함수의 스택 프레임은 자신을 호출한 함수의 프레임을 가리키는 포인터를 가지고 있다. 따라서 스택을 계속 따라 올라가면 최상위(root) 함수까지 추적할 수 있다. 이것이 프로그램이 크래시(crash)될 때 스택 트레이스가 생성되는 원리이다.

## 배운 점:
- 프로그램 메모리는 Code, Data, Stack, Heap 4가지 영역으로 나뉜다.
- Java 에서 참조는 스택에, 객체/배열은 힙에 저장된다는 점을 명확히 이해했다.
- 함수 호출마다 독립된 스택 프레임이 생성되므로, 지역 변수의 격리와 스택 트레이스 생성 원리를 함께 이해할 수 있었다.
